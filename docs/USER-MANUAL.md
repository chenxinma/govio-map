# Govio Map 用户手册（简版）

> 面向企业内数据分析用户（分析师 / 业务分析岗），无需开发经验。
> 适用版本：v0.6.1。本手册只覆盖当前版本已交付的功能。

---

## 1. Govio Map 是什么

Govio Map 是一个「无限画布」式的数据分析工作台：你在右侧对话面板用自然语言提出取数与分析需求，AI 助手生成 SQL、从数据源加载数据、做对比分析并画图；每一步都以卡片节点的形式出现在左侧画布上，并自动连上血缘线。结果可以一键复跑验证、可以查看分析留痕、可以导出成一份能直接发给业务方的交付报告——「这个数怎么来的」全程可查。

```
数据源表 ──▶ SQL ──▶ DataFrame ──▶ 报告 / 图表
```

## 2. 安装与启动

### 2.1 前置条件

| 依赖 | 说明 |
|------|------|
| Node.js | 运行本应用必需 |
| govio-cli | 数据加载引擎。应用启动时会检查并**自动安装/升级**（需要本机有 `uv` 工具且能联网）；也可请管理员预先安装，终端执行 `govio-cli -V` 能输出版本号（≥ 0.6.0）即可 |
| AI 提供商 API Key | 至少一个。默认使用 DeepSeek，首次启动时在弹窗中输入（见第 3 节） |

### 2.2 启动步骤（Web 版）

```bash
npm install     # 首次使用：安装依赖
npm run dev     # 启动
```

启动后浏览器打开 **http://localhost:5173/** 即可使用；后端服务（端口 5174）随之自动启动，无需单独操作。

> 也可以不弹窗、改用环境变量提供 API Key：在项目根目录创建 `.env` 文件，写入
> `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `GEMINI_API_KEY` / `MISTRAL_API_KEY` 之一。

### 2.3 桌面版

Govio Map 也可打包为 Windows 桌面应用（Electron 安装包），企业分发场景请联系管理员获取，使用方式与 Web 版一致。

## 3. 首次配置

### 3.1 首次启动：输入 API Key

首次启动（本机还没有任何模型配置）会自动弹出「**配置 DeepSeek API Key**」窗口：

1. 在输入框粘贴你的 DeepSeek API Key（`sk-` 开头）；
2. 点击「**保存并启动**」。

若点了「取消」，对话输入框会保持禁用并提示「请先配置 LLM Provider（右上角设置）」——随时可以从顶栏的「设置」按钮补配。

### 3.2 顶栏「设置」：更换提供商 / 模型

点击顶栏右侧 **齿轮图标（设置）** 打开「LLM 设置」：

| 配置项 | 说明 |
|--------|------|
| Provider 名称 | 可改名、可删除（垃圾桶图标） |
| Base URL | 提供商的 API 地址 |
| API 类型 | 接口协议，如 `openai-completions` |
| API Key | 该提供商的密钥（密码框） |
| 模型列表 | 每行「模型 ID + 显示名称（可选）」，可「添加模型」/ 删除 |
| 添加 Provider | 底部虚线按钮，新增一家提供商 |

填写完整（每个 Provider 都有名称、Base URL、API 类型和至少一个模型 ID）后点「**保存**」。保存即生效，后端会以新配置重启对话会话（历史会话仍可在「历史会话」中找回，画布不受影响）。

### 3.3 对话中切换模型

对话面板底部有「**模型**」下拉框，列出已配置的所有模型，选中即切换当前会话使用的模型。

## 5. 画布与五类节点

### 5.1 五类节点一览

| 类型 | 颜色标识 | 卡片内容 | 谁创建 |
|------|----------|----------|--------|
| 数据源表 | 紫色左边框 | 表名、数据源类型徽标、库名、行数、全限定表名（可复制）、字段列表（PK/FK 标签） | AI 查询表结构后展示 |
| SQL | 绿色左边框 | SQL 语句（关键字高亮）、输出列标签 | AI 生成 / 工具栏手动新建 |
| DataFrame | 橙色左边框 | 名称、数据源、行×列、内存占用、列结构表（列名/Non-Null/类型）、漂移警告 | AI 加载数据后自动创建 / SQL 编辑器执行 / 数据源面板添加 |
| 报告 | 琥珀色（差异）/ 紫色（相关性）左边框 | 报告类型、对比对象标签、Markdown 正文（可滚动） | AI 做差异对比 / 相关性分析 |
| 图表 | 蓝色左边框 | Plotly 图表（柱状/折线/散点/饼/环形/矩形树图等）、来源 DataFrame 标签 | AI 生成 |

所有节点卡片底部都有「**引用**」按钮和**删除**（垃圾桶）按钮。

### 5.2 每类节点能点什么

**数据源表节点**
- 头部徽标显示数据源类型（如 DUCKDB），悬停可看数据源名；
- 「全限定名」行显示 SQL 中应使用的完整表引用名，点**复制图标**一键复制（成功显示对勾）；
- 字段默认显示前 6 个，点「+N more fields」展开全部 / 「Collapse」收起。

**SQL 节点**
- 「**编辑**」按钮打开全屏 SQL 编辑器（见第 10 节）；也可直接**双击 SQL 文本**就地编辑（Ctrl+Enter 保存，Esc 取消）；
- 「**详情**」按钮展开分析留痕（见 7.3，仅 AI 生成或编辑器保存过的节点有）。

**DataFrame 节点**
- 「**预览**」弹出可拖拽的悬浮数据面板：显示真实数据（最多前 50 行），每页 10 行可翻页，右上角 X 关闭；
- 「**详情**」展开分析留痕（见 7.3）；
- 「**复跑**」一键验证结果可复现（见 7.1）；复跑状态条显示结论，点「N 次」可展开历次复跑记录；
- 列结构表超过 10 列时可展开/折叠；
- 出现漂移时：头部显示「漂移」警告标签、卡片边框变橙色（见 7.2）。

**报告节点**：正文可滚动阅读；「引用」可让 AI 基于报告继续加工。

**图表节点**：「**放大**」全屏查看（Esc 关闭）；配置异常时显示「图表配置错误」。

### 5.3 画布基本操作

| 操作 | 方式 |
|------|------|
| 移动节点 | 按住卡片拖拽（自动吸附网格） |
| 缩放 / 平移 | 滚轮缩放，拖空白处平移，左下角按钮缩放/适配 |
| 手动连线 | 从节点**右侧圆点**拖到另一节点**左侧圆点** |
| 自动连线 | 新建节点会按引用关系自动连线，无需手动操作 |
| 删除 | 卡片上的垃圾桶按钮 |
| 查找节点 | 顶部查找栏输入标题关键字，显示「N 个匹配」，按 Enter 循环定位并居中，Esc 或 X 清除 |
| 全局概览 | 右下角小地图（节点按类型着色） |

画布右上角工具栏：

| 按钮 | 功能 |
|------|------|
| **SQL** | 手动新建一个空白 SQL 节点（随后双击或点「编辑」写 SQL） |
| **导出交付报告** | 把整个画布导出为单文件 HTML 交付报告（见 7.4）；画布为空时禁用；导出中按钮转圈，完成后显示文件名与体积提示 |

## 6. 对话取数基本流

### 6.1 一次完整取数

1. 确认对话面板右上角是绿点「**已连接**」；
2. 在输入框用自然语言提问，如「按区域统计客户账单」「分析账单与收款的相关性」，按 **Enter** 发送（**Shift+Enter** 换行）；
3. AI 流式回复：可展开「思考过程」，工具调用显示为胶囊标签（转圈=执行中，绿勾=成功，红叉=失败）；
4. 画布上自动出现 SQL、DataFrame 等节点，并按血缘自动连线；
5. 点 DataFrame 节点的「**预览**」查看数据，点「**详情**」查看这份结果怎么来的。

### 6.2 插队与停止

- **插队**：AI 正在输出时继续输入并发送，新消息会立即插入，纠正 AI 的下一步动作；
- **停止**：点输入框右侧红色**停止**按钮，中止当前输出。

### 6.3 引用节点提问（正确姿势）

点任意节点卡片底部的「**引用**」，节点会变成输入框上方的标签（点标签上的 X 移除），随下一条消息一起发给 AI。被引用节点的关键内容（SQL 全文 / DataFrame 名 / 表结构与全限定名）会作为上下文附给 AI。

| 引用什么 | 好处 |
|----------|------|
| 数据源表节点 | AI 直接使用卡片上的**全限定表名**写 SQL，避免「表不存在 / 引用有歧义」这类试错 |
| SQL 节点 | AI 在原 SQL 基础上修改口径，而不是重写 |
| DataFrame 节点 | AI 基于已加载的数据做二次加工（合并、聚合、分析），不必重新取数 |

可以一次引用多个节点（例如两张表 + 一段 SQL，让 AI 做关联分析）。

### 6.4 斜杠命令

输入框键入 `/` 弹出命令建议（上下键选择，Enter 确认，Esc 关闭）：

| 命令 | 类型 | 作用 |
|------|------|------|
| `/clear` | 内置 | 清理当前会话上下文并清空消息（开始新会话） |
| `/clear-canvas` | 内置 | 清空画布节点与消息 |
| `/export` | 内置 | 把当前会话（消息 + 画布）导出为 JSON 文件下载（`govio-session-日期.json`，机器可读快照） |
| `/sql` | 模板 | 向 AI 请求生成 SELECT SQL |
| `/analyze` | 模板 | 请 AI 分析当前数据质量 |
| `/release-df` | 模板 | 请 AI 释放所有已加载的 DataFrame（回收本机运行数据） |
| `/导入元数据` | 模板 | 从数据源导入表结构到知识图谱（补全数据源与 schema 后发送） |
| `/skill:名称` | 技能 | 调用 AI 已装载的专项技能（输入 `/` 时自动列出可用技能） |

模板类命令选中后只是把预设文字填入输入框，可修改后再发送。

### 6.5 数据源面板

点顶栏**数据源**按钮（数据库图标）打开：

| 区域 | 内容与操作 |
|------|-----------|
| 已配置数据源 | 本机可用的数据源列表；每项右侧的**上传图标**会在对话输入框预填「/导入元数据 数据源:xx schemas:」，补全 schema 后发送即可让 AI 导入表结构 |
| 已加载 DataFrame | 名称 / 行数 / 列数列表；点「**+**」把某个 DataFrame 补到画布上（已上画布的显示对勾） |
| 刷新按钮 | 重新读取数据源与 DataFrame 列表 |

> 注意：从数据源面板「+」补上画布的 DataFrame 节点没有分析留痕，因此没有「详情 / 复跑」按钮；由 AI 加载或 SQL 编辑器执行产生的节点才有。

## 7. 验证与交付

### 7.1 一键复跑：三态含义

DataFrame 节点若固化了 SQL（卡片上有「复跑」按钮），点击后系统会用**留痕里固化的 SQL 与数据源**重新执行一次，并对比行数与校验和。复跑不影响画布上已交付的结果。

| 状态 | 显示 | 含义 |
|------|------|------|
| 复跑中 | 转圈图标，按钮变「复跑中」并禁用 | 正在重新执行 |
| 复现一致 | 绿色「复现一致 · 时间 · N 行 × M 列」 | 结果与原留痕完全一致，这个数可放心交付 |
| 漂移 | 橙色警告条 + 差异摘要 | 结果与原留痕**不一致**（见 7.2） |
| 复跑失败 | 红色错误条 + 原因 | 重新执行出错（SQL 报错、数据源不可用等），原因直接显示 |

点状态条右侧「**N 次**」可展开全部复跑记录（最新在前，最多保留 20 条），每条含结论、时间、耗时与差异摘要，悬停可看原值→新值明细。

### 7.2 漂移警示怎么读

- 漂移 = 底层数据在你交付之后**变了**（行数、列结构或校验和与原留痕不一致）；
- 漂移时**原结果不会被覆盖**：卡片上的行×列仍是当初交付的那份数据，新旧对比在复跑记录里；
- 节点头部出现「漂移」标签、卡片边框变橙色，导出交付报告时也会如实标注；
- 再次复跑若结果一致，警告自动消除；
- 需要以新数据为准时，请让 AI 重新加载一份新的 DataFrame（不要在漂移节点上直接改数）。

### 7.3 「详情」：分析留痕

SQL 节点与 DataFrame 节点的「**详情**」按钮展开一份只读留痕（内部称 Manifest，即「分析过程的存证」）：

| 字段 | 说明 |
|------|------|
| 来源 | 这份结果怎么产生的：observe load（AI 加载）/ SQL 编辑器（人工执行）/ 助手消息 SQL / show dataframe |
| 数据源 | 从哪个数据源取数 |
| 执行时间 | 最近一次成功执行的时间 |
| 行 × 列 | 结果规模 |
| 校验和 | 结构哈希 + SQL 哈希（用于复跑比对，不含数据内容） |
| 生成模型 | 哪家提供商的哪个模型生成的 SQL；人工执行显示「—（人工执行）」 |
| 会话 / 权限决策 | 所属会话 ID；关联的权限确认记录 ID（未触发确认门时显示「未关联」） |
| SQL 全文 | 固化下来的完整 SQL，只读、不可编辑 |

### 7.4 导出交付报告

点画布右上角「**导出交付报告**」，浏览器下载一个**单文件 HTML**（`govio-delivery-report-日期-时间.html`），双击即可离线打开，可直接邮件/IM 发给业务方。内容包括：

| 章节 | 内容 |
|------|------|
| 报告头 | 导出时间、应用版本、节点/连线统计 |
| 节点卡片快照 | 五类节点的静态快照（表结构、SQL 全文、DataFrame 列结构与复跑记录、报告正文、图表静态图像） |
| 血缘图 | 从左到右的节点血缘示意，点节点可跳到对应卡片 |
| 附录 A：分析留痕 | 每个 DataFrame 的留痕总表（数据源 / 执行时间 / 行×列 / 哈希 / 生成模型 / 权限决策 / 最近复跑）+ 可展开的 SQL 全文 |
| 附录 B：权限确认记录 | 与画布节点关联的数据导出确认记录：时间、决策（允许/拒绝/编辑）、来源（用户亲手确认 / 全局放行自动 / 超时自动拒绝等）、命令原文与修改后命令 |

要点：
- 报告**不含数据行内容**（预览数据、图表原始数组都不导出），只含结构、口径与留痕——图表以静态图片呈现（个别渲染失败时降级为配置摘要并写明原因）；
- 漂移节点在报告中有醒目警示清单，且注明「卡片上的行×列仍是已交付的那份结果」；
- 需要 PDF 时，用浏览器打开报告后「打印 → 另存为 PDF」即可；
- `/export` 命令导出的 JSON 是机器可读的会话快照，与本报告的分工：一个给机器、一个给人。

## 8. 权限确认卡

**什么时候弹出**：当 AI 准备执行**带 `-o`（数据导出）参数的取数命令**时，对话区出现橙色「需要权限确认」卡片，展示完整命令原文，等你决策后才会执行。普通取数（不导出数据内容）不弹窗。

| 按钮 | 后果 |
|------|------|
| **允许** | 执行这条命令（仅本次） |
| **Accept All** | 本会话内后续同类命令自动放行，不再弹窗；清空或切换会话后恢复逐条确认 |
| **编辑** | 命令变为可编辑文本框，改完点「**执行修改后命令**」，AI 会改用你的新命令（未改动时按钮禁用；「取消」返回） |
| **拒绝** | 不执行，AI 会收到拒绝信息并调整方案 |

- **超时自动拒绝**：卡片弹出后 **5 分钟**无操作，系统自动按「拒绝」处理；
- 中止对话、清空/切换会话时，未决的确认卡也会自动按拒绝处理；
- 每一次确认（含 Accept All 期间的自动放行）都会写入审计记录，可在交付报告附录 B 中查证「谁批准了这次取数」。

## 9. 会话管理

| 事项 | 行为 |
|------|------|
| 自动保存 | 对话消息自动持久化；画布随会话一起保存（节点/连线变化后约 1 秒落盘），重开会话时画布一并恢复 |
| 浏览器刷新 | 画布内容保存在本机浏览器中，刷新页面不丢失 |
| 打开历史会话 | 对话面板头部**时钟图标** → 列表显示会话名称/时间/消息数 → 点击即切换（消息与画布一起恢复） |
| 删除历史会话 | 会话条目上悬停出现**垃圾桶**按钮，点击删除（该会话的画布快照与审计记录一并删除） |
| 加载更早消息 | 长会话只加载最近一页消息，点消息列表顶部「**加载更早消息**」向上翻页 |
| 清空会话 | `/clear`：重置 AI 上下文并清空消息，开始新会话；`/clear-canvas`：清空画布与消息 |

> 切换/清空会话会同时结束「Accept All」放行状态，并自动拒绝未决的权限确认。

## 10. SQL 编辑器

**入口**：SQL 节点上的「**编辑**」按钮（全屏编辑器）；或画布工具栏「SQL」新建空白节点后进入编辑。

| 功能 | 说明 |
|------|------|
| 代码编辑 | 语法高亮、行号；输入时自动补全画布上的表名 / DataFrame 名与列名 |
| Format 按钮 | 一键格式化 SQL（快捷键 Ctrl+Shift+F） |
| 数据源下拉 | 两种来源：`memory`（在**已加载的 DataFrame** 上做二次查询）或某个外部数据源（**从数据库抽取**） |
| 执行按钮 | 执行 SQL：成功后自动在画布创建 DataFrame 节点并与当前 SQL 节点连线（提示「加载成功，节点已创建」）；失败时在下方显示错误信息 |
| 保存 / 取消 | 保存 SQL 到节点（Ctrl+Enter）；取消关闭（Esc） |

在卡片上**双击 SQL 文本**可就地快速编辑（Ctrl+Enter 保存，Esc 取消），适合小改动。

> SQL 编辑器由你亲手执行，不触发权限确认卡；执行产生的 DataFrame 节点同样带分析留痕（来源标注为「SQL 编辑器」，生成模型标注为「—（人工执行）」）。

## 11. 常见问题（FAQ）

| 现象 | 原因与处理 |
|------|-----------|
| 输入框禁用，提示「未连接到服务器…」 | 后端未就绪。查看启动终端日志：常见原因是 govio-cli 缺失且自动安装失败（本机没有 `uv` 工具或无法联网）。请安装 uv 或手动安装 govio-cli（`govio-cli -V` 验证），然后重新 `npm run dev` |
| 输入框禁用，提示「请先配置 LLM Provider（右上角设置）」 | 尚未配置 API Key。点顶栏齿轮进入「LLM 设置」填写并保存（见 3.2） |
| 弹出「配置 DeepSeek API Key」但 Key 无效 | 保存后对话报错或无响应时，打开「LLM 设置」核对 API Key、Base URL 是否填对、余额是否充足 |
| AI 回复报「SQL 执行错误」（如 Catalog Error / Binder Error / does not exist） | 多为表的引用名不对（该用几段式限定名）。处理：**引用画布上的数据源表节点**再提问，让 AI 使用卡片上的全限定表名；报错里若带 "Did you mean …" 提示，直接把提示内容发给 AI |
| 加载失败后画布上没有 DataFrame 节点 | 正常行为：失败的加载不会上画布，避免把错误结果当成交付物。修正 SQL 后让 AI 重新加载 |
| 复跑显示「该节点没有分析留痕（Manifest），无法复跑」 | 该节点不是由 AI 加载或 SQL 编辑器执行产生的（如从数据源面板补上画布、或早期版本的历史节点），没有固化 SQL 就不能复跑。让 AI 重新加载一次即可获得带留痕的新节点 |
| 复跑失败，显示 SQL 错误 | 数据源侧发生了变化（表被删/改名、权限变化）。把错误信息发给 AI 排查，或联系数据源管理员 |
| 节点显示「漂移」 | 底层数据变了，见 7.2。原结果未被覆盖；需要新数据时让 AI 重新加载 |
| 交付报告附录 B 写「未获取到审计记录」 | 导出时后端审计通道不可用（如后端未运行）或记录与当前会话对不上（如刚切换过会话）。导出不受影响，但报告会如实注明缺少「谁批准了取数」的佐证；保持后端运行、在同一会话内导出即可获得完整附录 |
| 图表卡片显示「图表配置错误」 | AI 生成的图表配置有问题。把该图表节点「引用」后让 AI 重新绘制 |
| 点「预览」面板一直空白 | 该 DataFrame 可能已被释放（如执行过 /release-df）或运行数据被清理。让 AI 重新加载后再预览 |
| 对话面板红点「未连接」且刷新无效 | 后端进程可能已退出。回到启动终端查看报错，必要时重新 `npm run dev` |

## 12. 附录：术语小表

| 术语 | 含义 |
|------|------|
| 数据源 | 一个可连接的数据库配置（如某个 DuckDB 文件库、PostgreSQL 库），由管理员在本机 govio-cli 中预先配置 |
| DataFrame | 一次取数加载到本机运行环境的结果集（类似一张内存表），有名字、行数和列结构 |
| 血缘 | 画布上节点间的连线，表示「下游结果由上游数据/SQL 产生」的链路 |
| 全限定名 | SQL 中唯一定位一张表的完整写法（不同数据库段数不同），数据源表卡片上可直接复制 |
| 分析留痕 | 每个结果节点固化的「存证」：SQL 全文、数据源、执行时间、行列规模、校验和、生成模型等（内部称 Manifest），只读不可改 |
| 复跑 | 用留痕固化的 SQL 重新执行一次并对比结果，验证「这个数还能不能复现」 |
| 漂移 | 复跑结果与原留痕不一致——底层数据在交付后发生了变化；原结果不会被覆盖 |
| 校验和 | 对结果规模/列结构/SQL 计算的哈希值，用于复跑时精确比对 |
| 权限确认（确认门） | AI 要执行数据导出类命令前必须经过你批准的机制；每次决策都留审计记录 |
| 交付报告 | 「导出交付报告」生成的单文件 HTML：节点快照 + 血缘图 + 留痕附录 + 权限确认记录，离线可打开 |
