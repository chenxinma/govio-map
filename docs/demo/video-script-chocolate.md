## 素材事实（演示前核对，勿凭记忆）

## 场景 1 · 元数据问数（0:25–1:05）★ 0.7.0：SourceTable 标注

**画面**：对话面板输入 → 回答流式输出 → 画布自动落下 sourceTable 节点。过程消息自动折叠为「已处理」（0.7.0 对话体验）。

**操作与台词**：

1. 对话输入（自然语言）：
   > 「chocolate 数据源里有哪些表？fact_sales 的表结构和关联关系是什么？」

2. agent 查询知识图谱后回答，画布依次出现 **3 个 sourceTable 节点**（紫左边框）：
   - 节点头标注（0.7.0 新增）：**数据源 `chocolate` · DuckDB · schema `chocolate` · 全限定名 `chocolate.chocolate.fact_sales`**——SQL 引用从此有据可依
   - 字段结构：`order_id`、`amount`、`boxes_shipped`、`discount_pct`、`price_per_box`、`marketing_spend`……

3. **关联关系以 agent 文字回答 + 字段标注呈现**（⚠ 表间关系连线未实现，见文末「功能缺口」）：回答中列出 3 条多对一外键：fact_sales.product_id → dim_product、fact_sales.country_id → dim_country、fact_sales.channel_id → dim_channel。

**旁白**：
> 「先认识数据。表节点带着完整的出身证明——数据源、类型、全限定表名，外键关系也在回答里说清楚了，SQL 引用再也不用猜。」

**字幕**：`SourceTable 标注 · 表引用有据可依`

**运镜**：鼠标悬停节点头的全限定名标注，停留 2 秒；再扫过 fact_sales 的外键字段。

> **导演注意**：若「表间关系连线」在录制前实现（见文末功能缺口），本场景升级为——节点间自动连出 3 条外键边，画面效果显著增强，优先采用。

## 场景 2 · 自然语言加载 + 分析留痕（1:05–1:55）★ 0.7.0：Manifest / 权限审计 ★ 0.6.1：steering 插队

**画面**：对话输入一句分析请求 → SQL 节点 → DataFrame 节点依次出现并连线。

**操作与台词**：

1. 对话输入：
   > 「按国家统计 2022–2023 年的销售额和订单数。」

2. **趁 agent 流式输出时，直接追加第二句**（0.6.1 新能力：流式中插队发送，气泡显示「已排队/已送达」）：
   > 「顺便看看澳大利亚的月度趋势。」
   ——不用等回复说完，任务自动排队执行。

3. agent 生成 SQL 并执行，画布出现 **sqlQuery 节点** → **dataFrame 节点** `df_country_sales`（5 行 × 3 列）。
   打开节点详情，**Analysis Manifest 留痕**（0.7.0 核心）逐项可见：
   - SQL 全文、数据源、执行模型
   - 行列数：5 × 3、**结果校验和**（checksum）
   - 权限确认记录：取数确认留痕（命令改前/改后可回查）

4. 点击「预览」，弹出权限确认（读数据）→ 确认后面板打开，5 个国家数据一行行扫过。**确认动作本身也进了审计留痕。**

**旁白**：
> 「说需求，不说 SQL。更关键的是——每个结果都带着留痕：SQL 原文、行数、校验和、连你每一次确认都有据可查。这个数怎么来的，随时回查。」

**字幕**：`分析留痕 Manifest · 每个数可回查`

**运镜**：Manifest 面板逐项扫过 3 秒；预览数据滚动 2 秒后关闭。

## 场景 3 · 公司口径 + 口径冲突检测（1:55–2:55）★ 0.7.0：图谱定义注入 / 冲突黄色警示

**画面**：连续两句提问，先「正确口径」顺畅出数，再「错误口径」触发黄色警示——形成正反对比，是全片戏剧高点。

**操作与台词**：

1. 对话输入：
   > 「按渠道算营销 ROI，营销投入花得值不值？」

2. **图谱定义自动注入**（0.7.0）：回答展开 tool 调用行（0.7.0 可展开查看完整命令），可见本次自动注入的图谱实体——`m_marketing_roi` 指标定义、维度码值、字段标准；**SQL 按公司口径生成，不再自造口径**。画布出现 DataFrame `df_channel_roi`（3 行 × 4 列）。

3. **冲突演示**——对话输入一句口径偏离的请求：
   > 「用每箱售价乘出货箱数，算一下 2023 年各国家的销售额。」

4. agent 照做生成 SQL，但 **sqlQuery 节点亮起 ⚠ 黄色警示**（0.7.0 口径冲突检测）：
   - 差异说明：**计量列不一致**——图谱 `m_sales_amount` 定义为 `sum(amount)`，本次用 `price_per_box × boxes_shipped` 重算
   - 旁白强调产品态度：**宁可「存疑」亮灯，不静默放行**

5. 用 **Chat 一键展开 / 宽内容全屏**（0.6.1）把差异说明全屏展示 2 秒。

**旁白**：
> 「口径不是拍脑袋。提问时，系统自动把公司指标定义注入进来。而当你故意偏离口径——它不会假装没看见，而是亮起黄灯，告诉你差在哪。宁可存疑，不误报。」

**字幕**：`口径冲突检测 · 宁可存疑，不误报`

**运镜**：黄色警示节点特写 3 秒；差异说明全屏 2 秒。

## 场景 4 · 数据血缘 × 语义血缘 + 一键复跑（2:55–3:35）★ 0.7.0：语义血缘 / 复跑漂移

**画面**：镜头拉远，展示完整血缘链路——**绿色实线**（数据血缘）与**紫色虚线**（语义血缘，口径沿袭）交错，左上角图例（0.7.0 置于画布左上角）。

```
fact_sales ─┐(数据血缘·绿实线)
dim_country ─┼─▶ SQL ──▶ df_country_sales ──▶ chart
             │      └╌╌╌(语义血缘·紫虚线：m_sales_amount 口径沿袭)
```

**操作与台词**：

1. 鼠标沿血缘链路从左到右缓慢平移，紫虚线上浮现口径溯源标签：**本次引用的图谱实体（指标/维度/标准 ID）**。
2. 在 `df_country_sales` 节点点 **「复跑」**（0.7.0）：按固化 SQL 重新执行，对比行数与校验和——**一致，无漂移**，留痕追加一条复跑记录。
3. 旁白顺势讲漂移场景：「如果哪天数据源变了，复跑对比不上，节点会标记漂移警告——但原留痕保留，绝不静默覆盖。」

**旁白**：
> 「绿色是数据从哪来，紫色是口径从哪来。一条结论，两层血缘。还可以一键复跑——数据变了会亮漂移警告，但原来的留痕永远保留。」

**字幕**：`数据血缘 × 语义血缘 · 一键复跑守护结论`

**运镜**：全景 → 沿链路平移 → 复跑按钮特写 → 复跑结果「无漂移」停留 2 秒。

## 功能缺口（截至 0.7.0 实测）

| 缺口 | 现状 | 影响 |
|---|---|---|
| sourceTable 之间无关系连线 | 建边逻辑只覆盖数据血缘（引用/来源）与 sqlQuery↔sqlQuery 语义血缘；外键仅字段级 `references`/FK 徽标，`observe explore` 外键发现只出文字报告 | **已立项 X10（方案2：图谱 rel → 语义血缘紫虚线），本期录制暂不实现**；场景 1 按现状口径录制，功能落地后可升级为亮点镜头 |

## 风险与规避

| 风险 | 规避 |
|---|---|
| agent 生成的 SQL 与脚本示意不一致 | 脚本 SQL 仅作分镜示意，旁白不念 SQL 细节，画面以实际节点为准 |
| 表引用报 Catalog/Binder 错误 | 全程使用三段式 `chocolate.chocolate.*`，录制前跑通一遍全流程 |
| 「错误口径」请求被 agent 主动纠正而不触发警示 | 录制前实测措辞；必要时把「就按这个算法算」写死进请求句 |
| 校验和/Manifest 字段展示样式与脚本不符 | 以实际 UI 为准，旁白只讲「SQL、行数、校验和、确认记录」四个概念 |
| 画布节点自动布局位置重叠 | 录制前实测 dagre 布局，必要时手动拖开后再录 |
| 复跑出现真实漂移（数据被其它进程改动） | 录制前确保 chocolate.db 只读、无并发写入 |
