## 场景 3 · 公司口径：正确不打扰 + 偏离亮灯（1:55–3:00）★ 0.7.0：图谱定义注入 / 冲突黄色警示

**画面**：连续三句提问——第一句证明「正确口径不打扰」，第二句证明「偏离口径亮灯」——形成正反对照，是全片戏剧高点。

### 3A 正确口径（不亮灯：证明不误报）

1. 对话输入：
   > 「按渠道算营销 ROI，营销投入花得值不值？」

2. **图谱定义自动注入**（0.7.0）：回答展开 tool 调用行（0.7.0 可展开查看完整命令），可见本次自动注入的图谱实体——`m_marketing_roi` 指标定义、维度码值、字段标准；**SQL 按公司口径生成，不再自造口径**。画布出现 DataFrame `df_channel_roi`（3 行 × 4 列）。

3. **sqlQuery 节点无任何警示**——实测判定 `consistent`（口径一致）。旁白点出：「对了就不打扰，这是检测可信度的前提。」

### 3B 偏离口径（亮黄灯：全片高点）

4. 对话输入（⚠ **措辞纪律**：只点名要的指标，不把成分指标写进问句）：
   > 「用每箱单价乘发货数量，算一下 2023 年各国家的销售额。**只用这两列，不要引用 amount，也不要加对照列。**」

   > **为何必须加后半句**（实测踩过的坑）：agent 天性会额外给一列官方口径做对照，实测会话 `13-18-37` 里它就输出了 `SUM(amount) AS sales_amount_std`——因为官方口径在 SQL 里存在，`sql caliber` 判 `consistent`，**黄灯不亮**（gov-48 实证）。必须明确禁止对照列，让 `amount` 完全不出现。

   > **为何这样问**：检测范围是「问题点名的指标」。若说成「用每箱售价乘**出货箱数**，算一下销售额」，问句会同时点名 `m_boxes_shipped`，正确口径的 SQL 也会因「未算箱数」被误报（实测）。用「每箱单价 / 发货数量」这类普通说法，只点名 `m_sales_amount`（实测验证）。
5. agent 生成 SQL，**sqlQuery 节点亮起 ⚠ 黄色警示**（0.7.0 口径冲突检测）：
   - 差异说明：**聚合口径 + 计量列**——图谱 `m_sales_amount` 定义为 `sum(amount)`，本次用 `price_per_box × boxes_shipped` 重算，`amount` 未参与
   - 旁白强调产品态度：**宁可「存疑」亮灯，不静默放行**

6. 用 **Chat 一键展开 / 宽内容全屏**（0.6.1）把差异说明全屏展示 2 秒。

**旁白**：
> 「口径不是拍脑袋。提问时，系统自动把公司指标定义注入进来。而当你故意偏离口径——它不会假装没看见，而是亮起黄灯，告诉你差在哪。对了不打扰，错了不放过。」

**字幕**：`口径冲突检测 · 对了不打扰，错了不放过`

**运镜**：3A 正确结果停留 2 秒（无警示的「干净」状态）→ 3B 黄灯节点特写 3 秒 → 差异说明全屏 2 秒。

> **录制注意**：若 agent 把计算列主动改名为 `revenue_calc` 一类「非指标名」，则本次不算「声称该指标」，判定为 `unknown`（不亮灯）——这是当前设计边界（PD-2 方案 C 待落地）。遇到此情况：重录该句（换种说法让它输出 `sales_amount` 列名），或改用「只用单价×数量算，不要用 amount」的硬缺失措辞（实测必 conflict）。

| 口径检测的别名归一（方案 C） | 检测范围 = 「问题点名的指标」；agent 主动把计算列改名（如 `revenue_calc`）则不算声称 → unknown 不亮灯 | PD-2 待讨论；录制期用干净措辞规避，遇改名则重录（见场景 3B 录制注意） |

## 风险与规避

| 风险 | 规避 |
|---|---|
| agent 生成的 SQL 与脚本示意不一致 | 脚本 SQL 仅作分镜示意，旁白不念 SQL 细节，画面以实际节点为准 |
| 表引用报 Catalog/Binder 错误 | 全程使用三段式 `chocolate.chocolate.*`，录制前跑通一遍全流程 |
| 「错误口径」请求被 agent 主动纠正而不触发警示 | 先录 3A 正确口径作对照（本就不应亮灯）；3B 若被纠正，改用「**只用**单价×数量算，不要用 amount」的硬缺失措辞（实测必 conflict） |
| 问句同时点名多个指标（如写「乘出货箱数」） | 会把计算成分当诉求 → 正确 SQL 也亮灯；录制时禁用带指标全名的成分描述（用「发货数量」代替「出货箱数」） |
| 校验和/Manifest 字段展示样式与脚本不符 | 以实际 UI 为准，旁白只讲「SQL、行数、校验和、确认记录」四个概念 |
| 画布节点自动布局位置重叠 | 录制前实测 dagre 布局，必要时手动拖开后再录 |
| 复跑出现真实漂移（数据被其它进程改动） | 录制前确保 chocolate.db 只读、无并发写入 |

## 口径冲突触发条件（govio-cli 0.7.2 实测，录制必须遵守）

检测范围 = **问题点名的指标**（问句里出现指标名/编码）；判定依据 = SQL 事实 vs 指标 `formula` + `measure` 列。

| SQL 形态 | 判定 | 黄灯 | 备注 |
|---|---|---|---|
| `SUM(price_per_box*boxes_shipped) AS sales_amount`，**不含 amount** | conflict | ✅ **必中** | 计量列 amount 未引用（推荐的 3B 形态） |
| `SUM(amount*(1-discount_pct/100)) AS sales_amount`，amount 被修饰 | conflict | ✅ | 聚合参数与 formula 不一致 |
| `AVG(amount)` | conflict | ✅ | 聚合函数不一致 |
| `SUM(price*boxes) AS sales_amount` **+ 另给 `SUM(amount) AS std`** | **consistent** | ❌ | **实测踩坑点**：官方口径存在即视为按口径实现 |
| `ROUND(SUM(amount),2)` | consistent | ❌ | 正确口径本就不打扰（3A 用） |
| 问句点名指标但 SQL 完全没算它 | conflict | ✅ | 计量列全部未引用 |

**录制纪律（三B）**：措辞必须同时满足 ——
1. 只点名目标指标（不要写「出货箱数」等指标全名，用「发货数量」）
2. **禁止 `amount` 出现**（写「不要引用 amount」）
3. **禁止对照列**（写「不要加对照列」）
